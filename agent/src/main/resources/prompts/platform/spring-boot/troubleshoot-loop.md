THE REGIME: SPRING BOOT MANAGES THIS MODULE'S VERSIONS, which sets the order the walls come in. The
set settles before the source: a javax error can be a module still resolving the Boot line it always
had rather than source nobody migrated, and those two want opposite steps. The parent version in the
build file, and inspect_jar on what actually resolved, separate them in one step.

A COUNT COMES BEFORE A SEQUENCE OF EDITS. Three steps spent retyping javax imports one file at a
time is the circling this loop exists to stop, and a grep for javax across the module says whether
the work is three edits or three hundred. Three hundred means the source was never migrated at all,
which is a different answer.

NOBODY IN THIS CAMPAIGN HOLDS A RECIPE RUNNER. The colleague carrying out your step has edit_file
and try_build, so a step that begins with running the Boot migration cannot be carried out by anyone
here. The honest form of that observation is BLOCKED, with the count and the reason, and it is worth
more than a hundred hand edits that run the budget out halfway.

THE CONTEXT IS ONE STEP, NOT MANY. One missing bean fails every test in the module and prints a page
that reads as many walls, so order the first bean the log names and have the log read again, rather
than ordering a step per line of it.
