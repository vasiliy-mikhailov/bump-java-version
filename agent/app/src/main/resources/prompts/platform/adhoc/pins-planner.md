NOTHING MANAGES THIS MODULE'S VERSIONS. Every row declared_versions prints for it carries a
number the module itself wrote, so there is no manager to move instead of the artifact, and
each floor it sits below is its own item in the plan.

A row that names a manager is the exception, and it is worth settling before planning
anything else: where an artifact is managed, declared_versions prints the manager's
coordinates in place of the version, and on a module answered adhoc there should be none.
Where one appears, that artifact is managed after all, and a version written here overrides a
set nothing else will reconcile. Name the artifact and its manager rather than the number.

THIS LIST IS ONE ROW ON MOST HOPS, so the plan here is one line or none, and on the hops that
carry only lombok a module that never declares it is finished before you start. Everything
this phase used to plan is planned at after-pins now, behind a compile. What is left is what
javac cannot start without, and on an unmanaged module the only open question is where that
version is written.

LOMBOK HIDES IN PLACEMENTS THAT ARE NOT A DEPENDENCY BLOCK, and where it lives is what the
plan owes the next agent. declared_versions prints the placement in its own column, so read
that column rather than the coordinate: a provided or compileOnly dependency, a property the
dependency reads, the annotationProcessorPaths of the compiler plugin, or, on Gradle, the
same coordinate twice because the module names it once to compile against and once as the
processor. Two rows of one coordinate are one item in the plan and land on one number.

ON THE HOP THAT CARRIES THE KOTLIN ROW, THE COORDINATE IN THE ROW IS NOT WHAT ANY MODULE
DECLARES. org.jetbrains.kotlin:kotlin is the head of a line rather than an artifact anybody
writes: a module on that line declares kotlin-stdlib, kotlin-maven-plugin, or the Gradle
plugin by its id, and the compiler and the library both have to reach the row's version. A
plan that names the coordinate in the row has named nothing this module can be pinned at, and
a plan that names the library alone leaves the compiler below the floor, which is where the
silent fallback the row describes happens. This project has made the first mistake before, on
an artifact called spring-boot that no application declares, and it read as every pin met.
