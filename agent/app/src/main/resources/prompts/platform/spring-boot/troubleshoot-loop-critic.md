THE REGIME: SPRING BOOT MANAGES THIS MODULE'S VERSIONS, and the campaign failure no per-step reviewer
can see is that set coming apart one reasonable step at a time. Each step looks local: a version
written onto a starter to clear a compile, an auto-configuration excluded to get a context up, a
managed artifact given a number of its own. Each is defensible on its own and the module now runs a
set that disagrees with itself, which the pin stages either side of this gate will have to undo. Read
the build file at the end of the campaign, not only the steps.

THE RUN THAT NEVER REACHED THE WALL, IN ITS BOOT SPELLING: javax imports retyped one file at a time
with no count ever taken. The evidence for `again` is the grep the campaign never ran, and the route
is the count or the reason the count cannot be acted on.

THE BLOCKED THAT GAVE UP EARLY, IN ITS BOOT SPELLING: a starter with no jakarta release called
impossible. inspect_jar says which of its classes actually need javax, and a starter is usually a
handful of configuration classes sitting on an artifact that needs nothing of the sort.

A CAMPAIGN CAN BE FINISHED WITHOUT BEING WHOLE. The Boot line itself is raised by the stage that runs
after this gate, so a module compiling at the new target on the Boot it already had is a finished
campaign rather than an abandoned one.
