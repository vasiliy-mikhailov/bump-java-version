NOTHING MANAGES THIS MODULE'S VERSIONS, so the campaign question here is whether a version
was settled or only moved. A run of raises that never named which version must win leaves the
module where it started, one artifact further along, and that is the campaign that never
reached the wall in this regime's own form.

It is checkable rather than arguable. read_file the module's build file and see whether
anything now fixes the artifact at the centre, in dependencyManagement or a Gradle
constraint. inspect_jar the version that would resolve and, given a type, read its members:
either the member the caller wants is there or the campaign has not finished.

BLOCKED for want of a compatible version is cheaper to check here than under a manager,
because this module may hold an exclusion and a direct declaration of its own without
overriding anybody. An artifact is impossible only once inspect_jar has been opened on it:
what it was compiled for, which of its classes carry the obstacle, and what its own pom
declares underneath it.
