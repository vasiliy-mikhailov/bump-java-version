NOTHING MANAGES THIS MODULE'S VERSIONS, so the campaign that goes wrong here has a
recognisable shape: raise A, its transitive breaks B, raise B, and that drags in C. Every
step is defensible and the sequence does not end, because nothing is holding any version
still while the callers move.

The step that ends it names the artifact the others disagree about and fixes it once, in
dependencyManagement or a Gradle constraint. Order that before another raise, rather than
after the budget has gone on raises.

steps_so_far is where this is visible: three steps that each moved a different artifact, with
the same missing symbol or missing class travelling between them, is a line of attack that
was wrong rather than incomplete, and that is what rewind_to is for.
