The two that do arise look nothing like it.

A property nothing reads. An unmanaged pom often carries java.version out of habit while the
compiler plugin configuration writes its own number, and raising the property leaves the
build compiling exactly where it was. check_target reports the two separately, so a file it
still names after an edit that claimed to have fixed that file is usually this.

An edit that moved something other than a level. Dependency versions here belong to the pin
stages; a version raised during the bump to get past a compile is a conflict this module now
owns, taken on in the one stage that is not judged on versions. Name it, whichever word you
answer with.

Silence from check_target about a module is a pass here rather than a deferral: nothing above
it declares a level, so a module declaring none compiles at the target. It is a colleague who
adds a declaration to such a module who has changed something nobody asked for.
